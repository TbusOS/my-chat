同一任务，不同提示词，天壤之别

示例 1: 写邮件

BAD 坏提示词
帮我写一封邮件
AI 输出泛泛而谈的模板邮件，没有任何针对性，需要大量修改才能使用...
GOOD 好提示词
以项目经理身份，给客户王总写一封邮件，告知项目延期2周，原因是供应链问题，语气诚恳但专业，200字以内
王总您好，关于XX项目进度，由于近期供应链波动导致关键组件交付延迟，项目预计延期两周...

示例 2: 代码审查

BAD 坏提示词
看看这段代码
这段代码整体还不错，建议可以优化一下变量命名，增加一些注释...
GOOD 好提示词
作为安全工程师审查这段 Node.js 代码，重点检查 SQL 注入、XSS 和认证漏洞，给出具体行号和修复方案
第23行: SQL 注入风险 - 直接拼接用户输入到查询语句
修复: 使用参数化查询 db.query('SELECT * FROM users WHERE id = ?', [userId])
好提示词的 5 个要素
🎭
角色 (Role)
"你是..." 定义 AI 的专家身份，让它以特定视角思考
🎯
任务 (Task)
明确说清楚要做什么，一个提示词聚焦一个任务
📏
约束 (Constraints)
字数、格式、语气、范围等限制条件
📝
示例 (Examples)
Few-shot: 给 1-3 个期望输出的例子让 AI 学习模式
📤
输出格式 (Format)
JSON? Markdown? 表格? 明确期望的输出结构
提示词膨胀 — 规则太多 = 没有规则
规则数量: 5 正常运作
AI: 收到! 5 条规则我都记住了，我会严格按照每一条执行。让我逐一确认...
✓ 规则 1 - 已理解 ✓ 规则 2 - 已理解 ✓ 规则 3 - 已理解...
为什么会这样？
注意力稀释
模型注意力是有限的，规则越多每条分到的注意力越少，重要规则被淹没
规则冲突
"回答要详细" vs "回答要简洁" — 模型不知道听谁的，两头不讨好
上下文污染
规则占据了宝贵的上下文空间，留给实际任务的空间变少
优先级模糊
50 条规则没有明确优先级，模型自己猜哪条更重要
最佳实践
System Prompt
5-10 条核心规则，不超过 500 tokens，只留最关键的
CLAUDE.md
项目级规则，聚焦"什么必须做"和"什么绝不能做"
不要重复
如果规则已在 System Prompt 中，不要在 CLAUDE.md 中重复
用 Skills 封装
复杂逻辑打包成 Skills，而不是堆砌成一堆规则
Skills = 提示词 + 工具 + 工作流
/review-code Skill 解剖
提示词 (Prompt)
"作为安全工程师，
审查代码中的安全漏洞，
重点关注注入攻击和认证..."
工具 (Tools)
Read — 读取文件内容
Grep — 搜索代码模式
Edit — 修改文件
工作流 (Workflow)
1
读取目标文件，理解代码结构
2
搜索已知的安全漏洞模式
3
输出安全审查报告 (Markdown 格式)
4
自动修复可修复的问题
Agent 更喜欢什么类型的 Skills？
🥇
结构化指令型 — Agent 最爱
/deploy — 1.检查测试通过 2.构建Docker镜像 3.推送到registry 4.更新K8s
每一步都清晰，Agent 可以逐步执行和验证，失败时知道从哪一步重试
🥈
约束边界型 — Agent 也喜欢
可以修改 src/ 下的文件，不能修改 test/ 下的文件，不能删除任何文件
清晰的边界让 Agent 放心行动，知道什么能做什么不能做
🥉
目标导向型 — Agent 能用
/fix-bug — 修复 issue #123 描述的 bug，确保现有测试仍然通过
需要 Agent 有足够的推理能力来自行规划路径
❌
模糊描述型 — Agent 讨厌
"让代码更好"、"优化一下"
没有明确标准，不知道什么算"完成"，Agent 无法判断是否满足要求
❌
矛盾规则型 — Agent 崩溃
"改动要最小" + "全面重构"
两条规则互相矛盾，无法同时满足，Agent 陷入死循环
Prompt / Skills / Agent 三者关系
💬
Prompt (提示词)
单次指令，一问一答
"帮我写一个排序函数"
简单 / 直接 / 一次性
📚
Skills (技能)
可复用的任务模板
/sort-algorithm 选择最佳排序算法
提示词 + 工具 + 工作流
🤖
Agent (智能体)
自主决策的执行者
"修复所有高优先级 bug"
自主 / 多步 / 调用多个 Skills
Agent 调用 Skills， Skills 包含 Prompts
Agent > Skills > Prompts
进化时间线
2022-2023 — Prompt 时代
ChatGPT 发布后，提示词工程成为核心竞争力。链式思维(CoT)、角色扮演等技巧涌现，"提示词工程师"成为热门职位。
2023.11-2025 — 定制化时代
2023.11 OpenAI 推出 Custom GPTs；2025.2 Claude Code 发布；2025.10.16 Anthropic 发布 Agent Skills 开放标准，可复用技能模板正式登场。
2025-2026 — Agent 时代
人定义目标，Agent 自主规划 + 执行 + 验证。Agent 自动选择调用哪些 Skills，4% 的 GitHub 代码已由 Claude Code 编写。
提示词会消失吗？
Past
2022-2023

提示词工程是核心技能

ChatGPT (2022.11) 引爆 AI 应用，好的提示词 = 好的结果。

链式思维 (CoT)、思维树 (ToT) 等 50+ 提示技巧被提出。

Present
2025-2026

Skills + Agent 时代到来

2025.2 Claude Code 发布；2025.10.16 Anthropic 推出 Agent Skills 开放标准

Skills 封装常见提示词模式为可复用模板，用户不需要自己写复杂提示词

Agent 自动选择策略并调用 Skills，人只需表达意图

Future
2027+

提示词 → "意图表达"

AI 将自动推测你的需求，而不是等你说清楚

Skills 将自动生成和优化，而不是手写

Agent 将自主决定用什么策略，而不是人来指定

"提示词工程" 演变为 "AI 行为设计"

⚠️ 但提示词永远不会完全消失

  • ● 专业任务 — 越专业的任务越需要精确的提示词。法律、医疗、金融领域的 AI 必须严格遵循规范。
  • ● 性格定义 — System Prompt 定义 AI 的"性格"，这永远需要人来设计。你希望 AI 幽默还是严肃？保守还是激进？
  • ● 安全边界 — 边界条件和安全约束必须由人明确指定。AI 不应该自己决定什么可以做什么不可以做。
  • ● 形态演变 — "提示词工程"会演变为"AI 行为设计"(AI Behavior Design)。名字变了，本质没变 — 人类定义 AI 的行为规范。

术语表 Glossary

Prompt (提示词)
给 AI 的指令文本，告诉 AI 你要它做什么
System Prompt (系统提示词)
定义 AI 角色和行为的"底层"提示词，用户通常看不到
Few-shot (少样本)
在提示词中给几个示例让 AI 学习输出格式和风格
Zero-shot (零样本)
不给示例，直接要求 AI 执行任务
Chain-of-Thought (思维链)
要求 AI 展示推理步骤，先思考再回答，提升复杂任务准确率
Skills (技能)
打包好的提示词 + 工具 + 工作流的可复用组合，类似 AI 的"技能书"
Agent (智能体)
能自主规划和执行多步任务的 AI，可以调用多个 Skills 来完成目标
CLAUDE.md
Claude Code 项目级规则文件，放在项目根目录，定义项目特定的约束
Context Window (上下文窗口)
AI 能"记住"的最大信息量，包括系统提示词、对话历史和当前输入
Token
AI 处理的最小文本单位，大约 1 个中文字 = 1-2 个 token
Temperature (温度)
控制 AI 输出随机性的参数。低温度 = 确定性高，高温度 = 创造性强
Hallucination (幻觉)
AI 自信地编造不存在的信息，看起来很真但完全是假的
